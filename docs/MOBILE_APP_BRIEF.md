# موجز لجلسة جديدة: تطبيق تسعيرك الأصلي (أندرويد + آيفون)

> اقرأ `C:\dev\taseerak\CLAUDE.md` أولاً لتفهم المنتج وقاعدة البيانات، ثم هذا الملف كاملاً.
> **لا تعدّل أي شيء داخل `C:\dev\taseerak` ولا في قاعدة البيانات**؛ هذا المستودع تملكه الجلسة الرئيسية (القسم ٦).

## ١. الهدف
**تطبيق أصلي كامل**، وليس غلافاً للموقع. يُبنى من الصفر بواجهة أصلية، ويضم كل مزايا المنتج للمشتري والمورد، ويتصل مباشرة بنفس الخادم (Supabase) الذي يستخدمه الموقع.
- الموقع الحالي `https://taseerak.vercel.app` هو المرجع الوظيفي: افتحه وجرّب كل مسار قبل بناء شاشته، واقرأ كود الصفحة المقابلة في `C:\dev\taseerak\src\app` (قراءة فقط).
- لوحة الإدارة (`/admin`) **تبقى على الويب** ولا تُبنى في التطبيق.

## ٢. التقنية
- **Expo (React Native) + TypeScript (strict)** مع **Expo Router**.
- البناء والنشر عبر **EAS Build / EAS Submit**، وهذا يبني آيفون في السحابة بدون Mac. التطوير على ويندوز، والاختبار بـ Expo Go ثم Development Build على جوال حقيقي.
- `@supabase/supabase-js` مع تخزين الجلسة في `expo-secure-store`.
- **RTL أولاً**: `I18nManager.forceRTL` حسب اللغة (عربي وأوردو RTL، إنجليزي LTR)، مع إعادة تشغيل التطبيق عند تغيير الاتجاه. خط **Cairo** عبر `expo-font`.
- مكتبات مقترحة:
  - التنقل والبيانات: `expo-router`، `@tanstack/react-query`، `react-hook-form` + `zod`
  - الجهاز: `expo-notifications`، `expo-image-picker`، `expo-camera`، `expo-location`، `react-native-maps`
  - الصوت: `expo-speech-recognition` للإملاء الصوتي
  - أخرى: `expo-linking` للروابط العميقة، `expo-sharing`، `expo-file-system`، `expo-print`
- المستودع: `C:\dev\taseerak-mobile`، git **خاص**، خارج OneDrive.
- `bundleIdentifier` / `package`: `com.taseerak.app`. الاسم: **تسعيرك** (Taseerak).

## ٣. الكود المشترك: لا تُعِد كتابة المنطق
هذه الملفات في الموقع هي **مصدر الحقيقة** للتصنيفات والبحث والفئات. انسخها **كما هي** بسكربت `scripts/sync-shared.mjs`، الذي يقرأ من `C:\dev\taseerak` ويكتب إلى `src/shared/` مع تعليق «مولَّد — لا تعدّل». ثم شغّله كلما تغيّرت:
- `src/types/index.ts`: القطاعات، والمنتجات، والتخصصات، والوحدات، والمناطق والمدن، و`detectSubCategory`، و`getGroupedProducts`
- `src/lib/normalize.ts`، `productSearch.ts`، `catalogSuggest.ts`، `sellers.ts`، `supplierPacks.ts`
- `src/lib/phone.ts`، `deadline.ts`، `vat.ts`
- `src/lib/localDraft.ts`: فكرته فقط (حفظ المسودات). في التطبيق استخدم AsyncStorage بنفس المفاتيح والمنطق.

إذا احتاج ملف مشترك تعديلاً ليعمل في React Native (مثل استخدام `window`)، **اطلبه من الجلسة الرئيسية**، ولا تعدّل النسخة.

## ٤. الشاشات المطلوبة (تكافؤ كامل مع الموقع)
راجع الصفحة المقابلة في الموقع لكل شاشة. الترتيب حسب الأولوية:

**الدخول والإعداد**
1. الدخول بالإيميل وكلمة المرور، والدخول بالجوال + OTP عبر واتساب (حين يُفعَّل، `NEXT_PUBLIC_PHONE_OTP`)، ونسيت كلمة المرور.
2. التسجيل: «أبحث عن أسعار» أو «أقدّم أسعار»، ثم للمورد «مستقل» أو «شركة/محل».
3. الإعداد التدريجي (`/onboarding`): الموقع على الخريطة، والقطاعات، والباقات الجاهزة «ماذا تبيع؟»، ونوع الحساب والنشاط، والتوثيق اختيارياً.

**المشتري**

4. الرئيسية: طلباتي وحالاتها، وعدّاد المهلة.
5. **الطلب السريع**: كتابة، أو إملاء صوتي، أو تصوير. اقتراح الذكاء الاصطناعي و«هل تقصد»، ومشاركة الصورة مع الموردين، والحفظ التلقائي للمسودة.
6. الطلب التفصيلي: البحث الذكي، والمواصفات، والوحدات، وفئات الموردين، والمهلة، والتوصيل والموقع.
7. صفحة الطلب: مصفوفة العروض لكل مادة، والترسية لكل مادة، والإنهاء إلى أوامر شراء، وشارات «مباشر من البائع» أو «عن طريق وسيط» والتوفّر والتوثيق.
8. تفاصيل العرض، والصفقات وأوامر الشراء، والفاتورة الضريبية (عرض ومشاركة PDF)، وتأكيد الاستلام، والتقييم.
9. مشروع BOQ: رفع ملف Excel أو PDF.

**المورد**

10. لوحة المورد: الطلبات المطابقة لتخصصه ومنطقته.
11. **تسعير الطلب**: سعر لكل مادة، والضريبة، والإضافات، ومصدر السعر، والتوفّر، ومدة الصلاحية، والمرفقات، والترتيب التنافسي.
12. صفقاتي (التوصيل والفاتورة)، وأسعاري، وتخصصاتي، والفروع، والأداء.
13. **فريق العمل**: إنشاء رابط دعوة ومشاركته عبر واتساب، والأعضاء، والانضمام عبر رابط `/team/join/<token>`. العضو يعمل باسم الشركة: استخدم `rpc('acting_uid')` كما في الموقع.

**مشترك**

14. الرسائل (Realtime)، والإشعارات (Realtime مع فلتر `user_id`)، والإعدادات (اللغة، والملف، والمستندات، ونوع الحساب)، و**حذف الحساب**.
15. صفحات عامة: أسعار المواد، ودليل الموردين، والخصوصية، والشروط.

## ٦. تقسيم العمل مع الجلسة الرئيسية
**هذه الجلسة تملك:** مستودع `taseerak-mobile` بالكامل.

**الجلسة الرئيسية (`C:\dev\taseerak` + قاعدة البيانات) تنفّذ عند الطلب:**
| المطلوب | لماذا |
|---|---|
| قبول `Authorization: Bearer <access_token>` في مسارات الـ API (حالياً تقرأ الكوكيز فقط): `quick-request/parse`، `quick-request/identify`، `parse-boq`، `match-spec`، `compare-offers`، `assistant`، `upload-attachment`، `verify-cr`، `file`، `classify-supplier` | التطبيق لا يملك كوكيز الموقع |
| جدول `device_tokens` + دالتا `register_device_token(token, platform)` و`unregister_device_token` | تسجيل الأجهزة |
| Edge Function لإرسال Push عبر FCM HTTP v1 عند إضافة صف في `notifications` | الإشعارات |
| **حذف الحساب** (دالة RPC + صفحة على الويب): شرط إلزامي في المتجرين | المتاجر |
| `/.well-known/assetlinks.json` و`apple-app-site-association` على الدومين | الروابط العميقة (تعطيها بصمة SHA-256 وTeam ID) |
| أي تعديل على الملفات المشتركة (القسم ٣) | مصدر واحد للحقيقة |

اكتب الطلبات في `taseerak-mobile/REQUESTS_FOR_WEB.md` بصيغة واضحة. المالك ينقلها للجلسة الرئيسية.

**قواعد الخادم التي يجب احترامها** (موجودة في قاعدة البيانات):
- RLS مفعّلة على كل الجداول. العمليات بين المستخدمين تمر عبر دوال `SECURITY DEFINER`، فاستخدم نفس الاستعلامات والدوال التي يستخدمها الموقع.
- `supplier_tier` تحسبه قاعدة البيانات، فلا ترسله أبداً. نوع البائع يُغيَّر عبر `rpc('set_seller_kind')`.
- هوية المقاول مخفية في `profiles_public`.
- ملفات الحاوية `licenses` خاصة وتُعرض عبر روابط موقّعة.
